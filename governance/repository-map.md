| Repository | Owns | Task record |
| --- | --- | --- |

For each repository touched, verify access/default branch/current tip, read root
and applicable nested AGENTS, then read its contribution/governance owners.
A map or generated context is navigation, not permission to edit a sibling repo.
Use one owning issue for a result and separate linked issues for independently
mergeable dependent work. Use full URLs across repositories. Do not copy source
verification or normative status into a publication to make it appear accepted.

## Worked routes

**New external report:** existing Subprime input issue → original-source/affected-use
report → maintainer decision → applicable source flow and reviewed PR → canonical
registry/brief/report reconciliation → completion comments. A UA conceptual
implication needs a linked UA issue and its own research/framework decision.
A site summary follows only the accepted owning editions.

**PMDay:** [site issue #2](https://github.com/oborskyivitalii/oborskyivitalii/issues/2)
owns article/edition → [UA transfer #133](https://github.com/UncertaintyArchitectureGroup/uncertainty-architecture/issues/133)
preserves PR #113 artifacts → [publishing #5](https://github.com/oborskyivitalii/oborskyivitalii/issues/5)
selects pinned reusable mechanics → rights/visual/editorial review → deliberate
publication. Neither a transferred file nor one merged dependency closes the
publication issue.
